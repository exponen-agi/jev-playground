Agentic systems: where Jev sits

Every multi-agent system, however it is wired, is full of small decisions between the agents. Is this output good enough to pass on? Who should go next? Does this conversation belong to a different agent now? Is the agent going round in circles? Is it done? Those decisions are usually made by another large model writing a string. Each of them is a typed, calibrated question Jev can answer in a quarter of a second, and that holds whether the agents are arranged in a line, side by side, or around a coordinator.

LLM agents do the workRead, plan, write, code, call tools. Nothing about them changes.
Jev makes the decisions between themOne call per decision point, typed answers, a probability on every one.
Your code holds the thresholdsBranches, budgets, arithmetic, and every bar that controls risk.

Where to be careful

      
    
        
  • Send a compact state. Accuracy drops as the state fills with material the question does not need, and agent transcripts grow fast. Send the task, the last output and a step count, not the history.
    • 
        
  • One judgement per question. "Who's next, and is it safe?" is two questions. Ask both in the same call and combine them in code.
    • 
        
  • Agent output is untrusted input. A worker that read a hostile web page can pass along text written to steer the router. Treat Jev as one layer of defence, not the only one.
    • 
        
  • Calibrate on your own runs. Calibration is a property of many answers taken together. Log answers next to outcomes, and set each bar from that log.
    • 
        
  • Jev doesn't plan or write. It chooses between options you name. Breaking a goal into steps and producing the text stay with the LLM agents.
    • 
        
  • Pin the version (jev-1.13.0) so a new release cannot quietly move your thresholds.
